AI code survival: weekly measurements

For each repository: how many lines were introduced by commits that carry machine-readable AI authorship metadata (Co-Authored-By trailers, bot authors, aider markers), and how many of those lines git blame still attributes to them at HEAD. These are counts, not grades. There is no rank, no colour and no verdict on this page; rows are alphabetical. Every row is reproducible with one command and the method and its limits are public.

Read this before reading the numbers

  • Only tagged commits are measured. Code from inline completions (Copilot, Cursor Tab, Windsurf, …) leaves no git trace and is invisible here. "No git signal" means absence of metadata, not absence of AI.
  • One commit can dominate a row. Ratios are line-weighted. A single bulk commit (a vendored tree, a docs snapshot, a generated bundle) can account for almost every introduced line; the row then measures that commit, not the project. Ratios are withheld below 5 AI-tagged commits, and rows where one agent holds ≥ 90 % of introduced lines are marked. Method v2 will cap per-commit weight and report intervals.
  • Survival is not quality. Deleted lines include removed features, moved code and rewritten prototypes; surviving lines include dead code. A formatter pass or a move between files counts as a death under method v1 (git blame without -w -M -C); method v2 fixes this.
  • Peer-reviewed context. Independent research on 201 projects (arXiv 2601.16809) finds agent-authored code is modified less often than human code. Read these counts alongside it.
  • Your repository, your call. Repositories are added by pull request. A maintainer can have theirs removed by adding one line to .github/survival-optout.txt; the next weekly run honours it, no questions asked.
