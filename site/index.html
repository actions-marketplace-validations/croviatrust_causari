re audit · works on any history, today

Everyone argues about how much code AI writes. Nobody can check the numbers.

re audit reads plain git history — Co-Authored-By trailers, bot authors, agent markers — finds the commits that carry machine-readable AI authorship, and asks git blame how many of their lines are still at HEAD. No model, no estimate, no survey. Anyone re-runs it and gets the same bytes.

--json

The exact bytes behind any published row. Diff them against ours.

--summary

Markdown for CI. No traffic lights, no "healthy": a count with its coverage statement.

--badge · --card

One-colour SVGs. The badge says what was counted; it does not judge the repository.

--save

Append a snapshot to .causari/audits/ and follow your own trend.

In CI, on every pull request

on: pull_request
permissions: { contents: read, pull-requests: write }
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }   # shallow clones are wrong
      - uses: croviatrust/causari@v1

The Action downloads the prebuilt Linux binary, runs re audit --summary, writes it to the job summary and keeps one sticky comment per PR. A live example.

What it cannot see

Code from inline completions (Copilot, Cursor Tab, Windsurf, …) leaves no git trace and counts as human. Commits without a trailer are UNKNOWN and excluded from the headline. A formatter pass or a moved function counts as a death under method v1. One bulk commit can dominate a line-weighted ratio; ratios under five AI-tagged commits are flagged.

All of this is written down at causari.dev/method, with how to reproduce or contest a number. The weekly measurements on open-source repositories follow the same rules: alphabetical, unranked, opt-out by pull request.

the ledger · from "which commit" to "which prompt"

Git remembers what changed. The ledger remembers what caused it.

If you also want to know why a line exists — the prompt, the model, the files the agent read — Causari records agent actions as they happen into a local, append-only ledger (.causari/, gitignored), with a snapshot of the tree before and after each one. Content-addressed with BLAKE3. Queried like git, answered with causes.

re init                     # .causari/, added to .gitignore
re hook claude-code         # every prompt and edit, exactly
re proxy                    # local LLM proxy: model, tokens, cost
re watch                    # attribute file changes to completions

re why    src/auth.ts:42    # which event introduced this line
re trace  src/auth.ts:42    # upstream, through reads and writes
re impact <event-id>        # downstream: what depended on it
re lens   src/auth.ts       # the file, line by line, by event
re bisect --test "npm test" # first recorded event that breaks it
re revert <event-id>        # restore the pre-state; recorded too
$ re why src/auth.ts:42

src/auth.ts:42  ⊢  introduced by event 2d070eb8cf
  agent:     claude-code
  tool:      Write
  evidence:  declared (agent lifecycle hook)
  prompt:    "Add a health-check endpoint returning
              build sha and uptime"
  reads:     spec/health.md, package.json
  writes:    src/auth.ts

$ re why src/legacy.ts:7

src/legacy.ts:7  ⊢  introduced by event 8f21c0aa19 (root)
  evidence:  correlated (score 1.00, 3/3 lines matched)

Two evidence classes, always printed

Declared — hooks, MCP, re record: the agent stated what it did. Exact prompt and path. With Claude Code the hook snapshots the tree right before the edit, so a human change between two agent edits is reported separately instead of absorbed.

Correlated — proxy + watch: the lines you inserted are searched inside completions captured moments before. A score, not a fact. The adversarial harness gives the measured numbers: 100 % on a clean write, 50 % after a formatter pass, wrong per-line attribution when two prompts touch one file in the same window.

What Causari refuses to do

No rank. No colour on a number. No "healthy" or "high churn". No badge about a repository we do not own. No public bot that audits your project unasked. No estimate where git carries no signal — the row says so.

Why: a measurement with a verdict attached stops being a measurement. The reasoning is in the manifesto; the plan to get there is in the roadmap, with exit criteria per phase.

⊢ proof · verifiable offline

A measurement nobody can check is an opinion.

re proof generate signs a manifest of the ledger — event count, sessions, agents, models, the content digest of the ledger itself — with a dedicated Ed25519 key, domain-separated from every other key the ledger owns. re proof verify needs the public key and nothing else: no server, no account, no trust in us. A modified manifest is rejected; unknown fields are rejected; a proof from an older schema is rejected by name.

$ re proof generate
proof: causari-proof.json
  128 events · 4 sessions · 36 files
  agents: claude-code, cursor
  badge:  causari-proof.svg

$ re proof verify --against-repo
ok   signature valid (Ed25519, causari.proof.v0.2)
     attests 128 events · 2 agents
     fresh: matches the current ledger

$ # someone edits the manifest…
INVALID  signature verification failed

Where this is going

The audit result itself will become a Crovia Seal (crovia.seal.v1): the audit JSON as subject, bound to the commit it measured and the method version that produced it, verifiable at causari.dev/verify with a static page and no network. The proxy will gain a PNX witness mode: a signed run sheet per agent session proving that no secret from a given set left the machine in the agent's traffic.

Those are Phase 2 of the roadmap and are not shipped yet. This page says "signed" only where something is signed today.

install

One binary. Verified download.

# Linux / macOS
curl -fsSL https://causari.dev/install.sh | sh
# Windows (PowerShell)
iwr -useb https://causari.dev/install.ps1 | iex
# Homebrew (macOS, Linux)
brew install croviatrust/tap/causari
# Scoop (Windows)
scoop bucket add causari https://github.com/croviatrust/scoop-bucket
scoop install causari

One program under two names: causari and re, both installed. The installers check the archive's SHA-256 against the release's SHA256SUMS.txt and abort on mismatch; the tap and the bucket render their manifests from the same file. From v0.2.0 every archive carries a signed SLSA provenance attestation (gh attestation verify). Prefer to build it yourself: cargo install --git https://github.com/croviatrust/causari.

MCP

re mcp exposes causari_record, causari_recall and causari_why over local stdio to Claude Desktop, Claude Code, Cursor, Windsurf and Cline. causari_record appends to .causari/ and never edits your source. Config snippets in the README.

Experimental

re skill, re brief, re guard, re churn and re sessions exist and are documented in the README. They are marked experimental: their output is not part of any proof and their interfaces may change.

Privacy

Everything lives in .causari/ next to your code. Prompts, models and reasoning never leave the machine. .env files are excluded from snapshots. Keys are written 0600. No telemetry — and this page loads nothing from anyone else.
